# 上线清单

从现在（后端和前端都写完、合并进 `main`，还没联调、没部署）到家里人真正用起来，按顺序做。

- **负责**：👤 你做（需要服务器、手机、账号、密码或拍板）；🤖 我做（改代码、跑测试、写文档）；🤝 一起（你操作，我给命令、看输出、排错）。
- **验收**：做完后能检查的结果。验收没过就不往下走。
- 做完一条就在这里打勾，并在“记录”里写一句（日期、结果、遇到的问题），方便下次接着做。
- 我碰不到服务器，也没有真机。服务器上的命令你执行，把输出贴给我；真机上的问题截图或录屏给我。

## 阶段 2：服务器部署（🤝 你在服务器上执行，我看输出）

完整命令在 [deploy/SERVER_STEPS.md](../deploy/SERVER_STEPS.md)，这里只列步骤和验收。每步的输出贴给我，我确认后再往下。
预计 40～60 分钟。2.9 会让 crab 中断几十秒，选个没人用的时间。

- [ ] **2.1 👤 确认能登录服务器**
  - 验收：`ssh` 能登上；`docker ps` 不用 sudo 就能执行。
- [ ] **2.2 🤝 只读检查现状（SERVER_STEPS 第 1 步）**
  - 验收：
    - crab-api 绑在 `127.0.0.1:8080`，crab-caddy 占着 80/443。
    - 8081 和 2019 端口空闲。
    - 域名 A 记录是本机公网 IP，没有 AAAA 记录。
    - 可用内存 2G 以上，磁盘剩余 5G 以上。
- [ ] **2.3 👤 配只读部署密钥（仅私有仓库，见 0.6）**
  - 服务器上生成密钥，公钥填到 GitHub 仓库 Settings → Deploy keys，不勾写权限。`~/.ssh/config` 另起一个 Host 别名，别和 crab 的冲突。
  - 验收：`ssh -T git@<别名>` 返回 `successfully authenticated`。
- [ ] **2.4 🤝 拉代码（2.1 节）**
  - 验收：`/opt/healthlog` 下 `git log --oneline -1` 是 1.10 合并后的提交。
- [ ] **2.5 🤝 写 `.env`（2.2 节）**
  - 验收：`PUBLIC_DOMAIN` 是 crab 的域名；`POSTGRES_PASSWORD`、`PRINT_TOKEN_SECRET` 都有值；`BASE_PATH` 为空。
  - 注意：`.env` 权限设成 600，别贴完整内容给我，贴 `grep` 出来的键名即可。
- [ ] **2.6 🤝 建数据目录（2.3 节）**
  - 验收：`ls -ln data/` 里 `storage` 的属主是 10001。
- [ ] **2.7 🤝 构建并启动（2.4 节，`./scripts/deploy.sh`）**
  - 验收：最后一行是 `✓ 部署完成`；`docker compose ps` 里三个容器都在运行，app 是 healthy；`curl -s localhost:8081/health/healthz` 返回 database 和 gotenberg 都是 ok。
- [ ] **2.8 👤 创建登录账号（2.5 节）**
  - 密码只你知道，至少 8 位。家里其他人要不要单独的账号见 4.3。
  - 验收：输出 `created account "..."`。
- [ ] **2.9 🤝 写网关配置并校验（第 3 步）**
  - 验收：`docker compose config` 输出 `compose ok`；`caddy validate` 输出 `Valid configuration`；`/opt/gateway` 用 git 提交了一次。
- [ ] **2.10 🤝 切换 80/443（第 4 步，crab 中断几十秒）**
  - 验收：网关日志出现 `certificate obtained successfully`；`ss -lntp` 里 80/443 属于网关。
  - 出问题按 SERVER_STEPS 第 6 步回滚，crab 马上恢复。
- [ ] **2.11 🤝 链路验证（第 5 步的 curl）**
  - 验收：
    - crab 的 `/api/` 有响应；`/t`、`/r` 返回 200。
    - `/health` 308 跳到 `/health/`；`/health/` 返回 200；`/health/api/me` 返回 401 JSON。
    - 响应头没有 `alt-svc`。
- [ ] **2.12 👤 crab 小程序打开看一眼订单列表**
  - 验收：和切换前一样能用。
- [ ] **2.13 🤝 配置每日备份（第 7 步）**
  - 验收：`crontab -l` 里有 3:10 的备份任务；手动跑一次 `backup.sh` 后 `backup/db/` 里有 dump 文件，`backup/storage/` 存在。
- [ ] **2.14 🤝 备份加密和异地同步（0.5 选了才做）**
  - 👤 在另一台机器（不是服务器）上用 `age-keygen` 生成密钥，私钥自己保管，公钥填进 `.env`。
  - 👤 建 COS 存储桶和子账号密钥，在服务器上用 `rclone config` 配好远端，远端名填进 `.env`。
  - 验收：再跑一次 `backup.sh`，dump 文件是 `.age` 结尾；`rclone ls <远端>` 能看到刚才的文件。

## 阶段 3：线上真机验证（👤 你拿手机，🤖 我看日志、修问题）

录音兼容性是这个产品最大的技术风险，这一阶段重点测它。
测试时建一个“测试”成员，数据都记在它名下，阶段 4 一次删掉。

- [ ] **3.1 👤 iPhone Safari：登录和录音**
  - 打开 `https://<域名>/health/`，登录，第一次按“按住说话”时允许麦克风。
  - 录 5 秒、10 秒各一段，上滑取消一段，不足 1 秒一段。
  - 验收：
    - 允许权限后再按就能录。
    - 取消和不足 1 秒的那两段没有保存。
    - 保存的两段在病程时间线上能播放，时长对得上，转码后声音正常。
- [ ] **3.2 👤 iPhone Safari：拍照和相册**

- [ ] **3.3 👤 安卓 Chrome：重复 3.1 和 3.2**

- [ ] **3.6 👤 场景一：孩子感冒**

## 阶段 4：正式启用和运维

- [ ] **4.1 👤 清掉测试数据**
  - 在成员管理里删除“测试”成员。只删成员，**不要用 `purge-data`**，它会删掉整个家庭的数据。

  - 验收：每台手机都能从主屏幕图标直接打开并记一笔，记的内容在其他人的手机上也能看到。
